# S-401: Add credit to a movie

**Epic:** E04 Credits and filmography  
**Priority:** Must · **Size:** M · **Order:** 20 · **Wave:** 6  
**Status:** Draft (Phase 4)  
**Depends on:** S-203, S-103  
**Requirements:** FR-CRD-01, NFR-TEST-03  
**BRD acceptance criteria owned:** AC-FR-CRD-01-2

## Objective

Add credit to a movie.

## Acceptance criteria

- `AC-FR-CRD-01-2`: as defined in `docs/requirements/BRD.md` section 10.
- `S-401.AC1`: Gateway `addCredit` calls `GetPerson` then `MovieService.AddCredit`; unknown person → field error `credit.person.not_found` (ADR-003).
- `S-401.AC2`: CreditEditor on the movie page: person picker (search by name via `people` list with paging), role select, character name for ACTOR only.
- `S-401.AC3`: Duplicate (movie, person, role) → `credit.duplicate` (EC-18); the same person with a different role is allowed (BR-04).
- `S-401.AC4`: `AC-FR-CRD-01-1` (credit appears on movie and person pages) is verified in S-404, which owns it.
- `S-401.AC5`: Unspecified or unknown role → `credit.role.invalid`; `characterName` is trimmed; gateway order is person check, then `AddCredit` (movie not found → `NOT_FOUND`).
- `S-401.AC6`: Contract change: `ListPeopleRequest.query` and `people(query:)` provide name search (substring, case-insensitive, min 1 char) for the person picker, so the picker works with 1,000 people.
- `S-401.AC7`: Liquibase changeset for `credit` (unique and check constraints per `data-model.md`) is part of this story.

## Business rules and edge cases

- BR-06: credits store person_id only; no cross-service foreign key.
- character name ≤ 200 and only for ACTOR (`credit.character.invalid`).

## Test expectations

- Unit: credit rules; Integration: unique constraint race.
- Contract: gRPC errors and gateway mapping.
- Component: picker states, ACTOR-only field.

## Definition of done

Apply `docs/backlog/definition-of-done.md` in full, plus the criteria above. No criterion is complete without command output as evidence.
