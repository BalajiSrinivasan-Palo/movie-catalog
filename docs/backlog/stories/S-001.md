# S-001: Repository and build scaffold

**Epic:** E00 Foundation and platform skeleton  
**Priority:** Must · **Size:** M · **Order:** 1 · **Wave:** 1  
**Status:** Draft (Phase 4)  
**Depends on:** none  
**Requirements:** NFR-TECH-02, NFR-ARCH-01, NFR-ARCH-02, NFR-MNT-03, NFR-PROC-01, NFR-REL-04, NFR-ARCH-04  
**BRD acceptance criteria owned:** none

## Objective

Repository and build scaffold.

## Acceptance criteria

- `S-001.AC1`: Clean checkout builds with the Gradle wrapper: `./gradlew build` exits 0.
- `S-001.AC2`: The three `.proto` files in `contracts` generate Kotlin/Java stubs consumed by all services.
- `S-001.AC3`: `movie-service`, `people-service`, `api-gateway` each start and report healthy through Actuator.
- `S-001.AC4`: Each service starts against an empty data directory and applies its Liquibase baseline (NFR-REL-04).
- `S-001.AC5`: Chosen dependency versions and the gRPC library decision are recorded in ADR-013 and ADR-004; every added dependency has a one-line justification.
- `S-001.AC6`: AC0 (blocker): dependency resolution from Maven Central and the Gradle plugin portal succeeds on the owner's machine; if it fails the story is blocked, not Done.
- `S-001.AC7`: `.gitignore` excludes `data/`, `build/`, `node_modules/`, `reports/`; Actuator on 8081 (movie) and 8082 (people); people-service has a configured gRPC client to movie-service; a check (`scripts/check_no_http_between_services.sh` or a Gradle test) fails if a service uses an HTTP client to call another service (NFR-ARCH-02).

## Business rules and edge cases

- No dependency without a justification in the architecture document (NFR-MNT-03).

## Test expectations

- Build smoke test (`./gradlew build`).
- Spring context-load test per service.
- Liquibase empty-start test.

## Definition of done

Apply `docs/backlog/definition-of-done.md` in full, plus the criteria above. No criterion is complete without command output as evidence.

## Notes

Runs on the owner's computer (D12). Maven Central reachability there must be confirmed first.

## Why this design (for the walkthrough)

A reproducible multi-module build is the foundation; version pinning is deliberately done here, not assumed earlier.
