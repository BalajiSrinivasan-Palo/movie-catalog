# Kotlin / Spring Boot conventions
- Layers: `grpc` (adapters) -> `service` (business rules, validation) -> `repository`. Controllers/adapters contain no business logic.
- Validation is authoritative in the service layer; return violations as `ErrorDetail` with BRD message keys (`docs/requirements/BRD.md` section 7).
- Use constructor injection, immutable data classes, `Instant` in UTC, UUID ids generated by the service.
- Persistence: Spring Data JPA, parameterised queries only; escape `LIKE` input with `ESCAPE '\'`. Schema changes only via Liquibase changesets, never edited after merge.
- Map exceptions to gRPC `Status` + `ErrorDetail` in one place (see ADR-005). Never leak stack traces or SQL.
- Tests: JUnit 5 + MockK; in-process gRPC channels for service tests; every validation rule has a pass and a fail test incl. boundaries. Name tests after the acceptance criterion they cover (`AC-FR-...`).
- Do not add a dependency without a justification line in the story plan.
- Formatting: ktlint and detekt must pass.
