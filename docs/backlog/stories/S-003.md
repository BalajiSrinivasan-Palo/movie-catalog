# S-003: Frontend scaffold, design system and shared feedback components

**Epic:** E00 Foundation and platform skeleton  
**Priority:** Must · **Size:** L · **Order:** 3 · **Wave:** 1  
**Status:** Draft (Phase 4)  
**Depends on:** none  
**Requirements:** NFR-TECH-01, NFR-UX-01, NFR-UX-03, NFR-UX-04, NFR-UX-06, NFR-A11Y-01, NFR-SEC-03, NFR-MNT-01, FR-EXT-02, FR-EXT-03  
**BRD acceptance criteria owned:** none

## Objective

Frontend scaffold, design system and shared feedback components.

## Acceptance criteria

- `S-003.AC1`: SvelteKit SPA (ssr off, adapter-static) builds; `svelte-check`, ESLint, Prettier, Vitest and Playwright configured and passing on the scaffold.
- `S-003.AC2`: Shell layout with header (logo, nav, search box slot) is usable at 360, 768 and 1280 px without horizontal scroll.
- `S-003.AC3`: Shared components exist with tests: Button (pending state), TextField/TextArea/Select (label, error, aria), Dialog (focus trap, Esc), Toast (aria-live), Skeleton, Pagination, ProgressBar (role=progressbar).
- `S-003.AC4`: GraphQL client wrapper maps `extensions.code`/`fieldErrors` to a typed error and supports AbortController.
- `S-003.AC5`: A lint rule forbids `{@html}` on user data (NFR-SEC-03).
- `S-003.AC6`: Shared components implement the failure and pending behaviour required by FR-EXT-02/03; `AC-FR-EXT-02-1` and `AC-FR-EXT-03-1` are owned and verified across all mutations and lists in S-603.
- `S-003.AC7`: `./scripts/verify.sh` runs svelte-check, ESLint, Prettier, Vitest with coverage and the build once `frontend/` exists, and fails when any fails.
- `S-003.AC8`: A message catalogue maps every `messageKey` in BRD section 7 to user text; a test enumerates the keys parsed from the BRD and fails when one is missing (NFR-UX-06).
- `S-003.AC9`: Interactive controls meet 44×44 px touch targets (checked by a component test on the shared components).

## Business rules and edge cases

- Form state machine: idle | pending | success | error; inputs are never cleared on error.

## Test expectations

- Component tests per shared component incl. keyboard behaviour.
- Client unit tests: success, GraphQL error, network error, abort.
- Fake-timer test for Toast.

## Definition of done

Apply `docs/backlog/definition-of-done.md` in full, plus the criteria above. No criterion is complete without command output as evidence.

## Notes

Large: may be split during refinement into scaffold (S-003a) and components (S-003b) if review time exceeds one sitting. Large: implement and review in two parts (3a scaffold, tooling and gate wiring; 3b components, client and message catalogue).

## Why this design (for the walkthrough)

Feedback behaviour is an explicit assessment criterion, so it is built once and reused rather than reimplemented per page.
