# S-701: Visual refresh: poster grid lists, cinematic detail pages and drag-and-drop artwork upload

**Epic:** E07 Visual refresh  
**Priority:** Should · **Size:** L · **Order:** 30 · **Wave:** 11  
**Status:** In progress (D21 approved); all parts (7a, 7b, 7c) implemented, unit tests not yet run, not reviewed (see `reports/S-701/7a-report.md`, `7b-report.md`, `7c-report.md`)  
**Depends on:** S-206, S-304, S-305, S-306, S-402, S-404, S-502  
**Requirements:** NFR-UX-01, NFR-UX-02, NFR-A11Y-01, FR-ART-01, FR-ART-03, FR-MOV-06  
**BRD acceptance criteria owned:** none

## Objective

The owner is not happy with the current look (grey header bar, solid blue tabs, plain lists). Restyle the app to the approved mockups: **Option A** (poster grid) for the movie and people lists, **Option C** (cinematic detail) for the movie and person detail pages, and a **drag-and-drop** drop zone for artwork upload. This is a presentation change only: no GraphQL, gRPC, validation or business-rule change. Large, so it is implemented and reviewed in three parts (7a, 7b, 7c; see the plan).

## Acceptance criteria

### 7a: design tokens, header and list pages (Option A)
- `S-701.AC1`: The header is a light bar with the brand, a "Movies / People" nav where the current page is a tinted pill (not a solid blue block) with `aria-current="page"`, and the search box on the right. Below 600 px the search box wraps to its own full-width row.
- `S-701.AC2`: The movie list is a poster grid: 2 columns below 600 px, 3 from 600 px, 5 from 960 px. Each card holds a 2:3 poster (thumbnail, or the existing placeholder), the title and "year · genres"; the title is the card's only link and is stretched over the whole card, so the card is one click target named by the title. No horizontal scroll at 360, 768 or 1280 px.
- `S-701.AC3`: Genres are shown as a single-choice chip row ("All" plus each genre). The chips are native radio inputs in a `fieldset` with a legend "Genre", so they are keyboard-operable (arrow keys) and announced as a group. Choosing a chip applies the genre at once and returns to page 1, keeping the applied sort and years (FR-MOV-06); sort and years still use Apply. Below 600 px the chips are one row that scrolls inside itself, so the page never scrolls sideways.
- `S-701.AC4`: The page heading shows the total count ("Movies · 128 titles") and a single primary "Add movie" action. Loading shows poster-shaped skeletons (NFR-UX-03), and the empty and error states keep their current wording.
- `S-701.AC5`: The people list uses the same grid with an initials circle (from the person's name, plain text) instead of a poster, name, and "born <date>" when known.

### 7b: detail pages (Option C)
- `S-701.AC6`: The movie detail page opens with a dark hero band containing a back link to Movies, the poster, the title as `h1`, "year · runtime · N credits", genre pills, the synopsis, and the Edit and Delete actions; the artwork uploader and Remove artwork follow directly below the hero. Below 600 px the poster stacks above the text.
- `S-701.AC7`: Credits are shown as cards (initials circle, name as a link to the person, "role · character"). A credit whose person is unavailable or not found is a dashed card that keeps the existing wording ("Name unavailable" or "Unknown person"), the role and the Edit and Remove actions; the existing add, edit and remove credit flows keep working.
- `S-701.AC8`: The person detail page uses the same hero band (name, "born <date>", biography, Edit and Delete), and the filmography is a poster grid of the person's movies (thumbnail or placeholder, title, "year · role"). The blocked-delete message and its list of movies stay as they are.
- `S-701.AC9`: Every text and background pair added for the hero band reaches 4.5:1, checked by the existing contrast test in `design-rules.test.ts` (NFR-A11Y-01).

### 7c: drag-and-drop artwork upload
- `S-701.AC10`: The artwork uploader shows a drop zone reading "Drag an image here or choose a file" with "JPEG, PNG or WebP · up to 5 MB". The "choose a file" control is the existing labelled `<input type="file">`, so keyboard and screen-reader users can still upload (NFR-A11Y-01).
- `S-701.AC11`: While a file is dragged over, the zone is highlighted and reads "Drop to upload" (and "Replaces the current artwork" when there is one). Leaving the zone restores it.
- `S-701.AC12`: A dropped file goes through exactly the same path as a chosen file: the same client pre-checks, progress, Processing…, Cancel, error and Retry (S-304 AC1 to AC5 still hold). If several files are dropped, only the first is used and a status message says so. Dropping something that is not a file, or dropping while an upload is running, does nothing.
- `S-701.AC13`: Dropping a file anywhere else on the page does not make the browser navigate away to the image.

## Business rules and edge cases

- Allowed artwork: JPEG, PNG, WebP up to 5 MiB; the server decision stays final (S-304 AC3). EC-08 (cancel leaves old artwork) unchanged.
- User text (titles, names, bios, synopses, character names) is still rendered as text, never with `{@html}`.
- No new runtime dependency, no icon font and no UI library (ADR-010); any icons are a few inline SVGs marked `aria-hidden`.
- Dark mode is out of scope.

## Test expectations

- Unit: initials helper (one name, several names, extra spaces, non-Latin letters).
- Component: chip group changes the URL filter and is keyboard-operable; poster card is a single link with accessible name; hero band renders all fields and the missing ones; unavailable-person card; drop zone dragenter/dragleave/drop with one file, several files, a non-file drag, and a drop while busy; dropped file goes through the same validation as a chosen one.
- Static: `design-rules.test.ts` extended with the new colour tokens and touch targets.
- Existing tests: every current component and view test still passes, updated only where markup changed (selectors), never to weaken an assertion.
- E2E (mocked suite): list, detail and upload journeys still pass; a drag-and-drop upload is added if Playwright's file drop works in the mocked setup, otherwise this is stated as not covered.

## Definition of done

Apply `docs/backlog/definition-of-done.md` in full, plus the criteria above. No criterion is complete without command output as evidence. Screenshots at 360, 768 and 1280 px of the list, detail and uploader are saved under `reports/S-701/`.

## Why this design (for the walkthrough)

The assessment app worked but looked plain. A poster-first list and a cinematic detail page match what people expect from a film catalog, and drag and drop is the expected way to add a picture. Keeping it CSS and markup only means no contract or service changes and every existing behaviour test still guards the change.
