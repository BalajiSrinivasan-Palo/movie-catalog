## Objective

Follow the owner's reference images (2026-10-22): a search box with a scope menu like IMDb's (All, Titles, People), a calendar-style picker for the "from" and "to" release years, and genre chips where several can be selected, each selected chip filled with a ✕. Movies store only a release year (BRD section 7), so the picker chooses years, not days (D22). Choosing several genres needs an additive contract change. A movie matches if it has **any** selected genre. Implemented and reviewed in three parts: 8a (search scope, frontend), 8b (year picker, frontend), 8c (multi-genre: contracts, movie-service, gateway, frontend).

## Acceptance criteria

### 8a: search scope
- `S-702.AC1`: The search box has a scope button on its left showing the current scope ("All", "Titles" or "People"). It opens a menu with those three options; the current one is marked. The menu works with the keyboard (Enter or Space or Down opens it, arrows move, Enter chooses, Esc closes and returns focus to the button) and is announced as a menu with checked items.
- `S-702.AC2`: The scope is kept in the address (`/search?q=…&scope=titles|people`; no parameter means All). "Titles" shows only the movie group and pages through `searchMovies`; "People" (cast and crew) shows only the people group through `searchPeople`; "All" keeps today's grouped result. All existing search states (too short, pending, empty, error, stale responses discarded, debounce) behave as before for every scope (FR-SRC-02, NFR-UX-05).
- `S-702.AC3`: The search box's label and placeholder follow the scope: "Search movies and people", "Search movies", "Search people" (the menu items read All, Titles, People (cast and crew)). After a choice, focus returns to the scope button (menu-button pattern) and the search box keeps focus while typing across navigations.

### 8b: year picker
- `S-702.AC4`: "From year" and "To year" each have a text field (typing still works) and a calendar button that opens a year grid: 20 years per page (pages aligned to multiples of 20, so the header reads for example "1980–1999"), previous and next page buttons, "Clear" and "This year". The selected year is highlighted; years outside 1888 to the current year + 5 are not offered, and the header shows only offered years ("1888–1899", "2020–2031"). Picking a year returns focus to the calendar button.
- `S-702.AC5`: The grid is keyboard-operable (arrow keys move by one year or one row, Page Up and Page Down change page, Enter picks, Esc closes and returns focus to the calendar button) and every year button is at least 44 px.
- `S-702.AC6`: Picking a year fills the field; the existing range check (`filter.year.invalid`) and the Apply button behave as before.

### 8c: multi-select genres
- `S-702.AC7`: Genre chips are a group of checkboxes (legend "Genre"); several can be selected. A selected chip is filled and shows a ✕; clicking it again removes it. Genres are sent in the fixed list order. There is no summary line under the chips and no "All" chip (owner, D23): none selected means all, and "Clear filters" removes every genre. Changing genres applies at once and returns to page 1.
- `S-702.AC8`: GraphQL `MovieFilter` gains `genres: [Genre!]`; protobuf `ListMoviesRequest` gains `repeated Genre genres = 7`. A movie matches when it has **any** of the listed genres. An empty list means no genre filter. The existing single `genre` field keeps working and is combined with `genres` (deprecated in GraphQL, kept in protobuf for compatibility).
- `S-702.AC9`: movie-service rejects more than 15 genres, duplicates or unknown values with `INVALID_ARGUMENT` and the existing key `movie.genres.invalid`; the gateway passes the error through as a field error (ADR-005). Results with several genres hold no duplicate movies, and the total count is correct.

## Business rules and edge cases

- Year range 1888 to current year + 5 (BRD section 7); from must not be after to (`filter.year.invalid`).
- Search query rules (2 to 100 characters, escaping) are unchanged; only which groups are fetched and shown changes.
- The scope menu and year grid are hand-built (ADR-010): no UI library and no new dependency.

## Test expectations

- Unit (frontend): scope from and to the URL; year grid page maths and bounds; genre summary text.
- Component: scope menu keyboard behaviour and roles; search per scope calls the right API function; year picker keyboard, bounds and focus return; genre checkboxes select several, ✕ removes, Clear, page reset.
- Backend (owner runs, D15): movie-service list with 0, 1 and 2 genres (any-match, no duplicates, correct count), validation of too many, duplicate and unknown genres; gRPC test for `genres`; gateway GraphQL test mapping `genres` and the deprecated `genre`.
- Contract: protobuf change is additive (field number 7, no renumbering).
- E2E (mocked): axe and responsive checks on the new controls; mock API supports `genres` and `scope`.

## Why this design (for the walkthrough)

The owner pointed to familiar patterns. The scope menu reuses search endpoints that already exist. The year picker gives the calendar feel the owner asked for while staying true to the data, which has years only. Multi-genre filtering is a small, additive contract change (one repeated field and one OR predicate), so old clients keep working.
