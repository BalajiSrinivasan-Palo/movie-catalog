# S-502: Search UI with debounce and full state handling

**Epic:** E05 Search  
**Priority:** Must · **Size:** M · **Order:** 26 · **Wave:** 6  
**Status:** Draft (Phase 4)  
**Depends on:** S-501, S-003, S-203, S-103  
**Requirements:** FR-SRC-02, FR-SRC-03, NFR-UX-05  
**BRD acceptance criteria owned:** AC-FR-SRC-02-1, AC-FR-SRC-02-2, AC-FR-SRC-03-1, AC-FR-SRC-03-2, AC-FR-SRC-03-3

## Objective

Search UI with debounce and full state handling.

## Acceptance criteria

- `AC-FR-SRC-02-1`: as defined in `docs/requirements/BRD.md` section 10.
- `AC-FR-SRC-02-2`: as defined in `docs/requirements/BRD.md` section 10.
- `AC-FR-SRC-03-1`: as defined in `docs/requirements/BRD.md` section 10.
- `AC-FR-SRC-03-2`: as defined in `docs/requirements/BRD.md` section 10.
- `AC-FR-SRC-03-3`: as defined in `docs/requirements/BRD.md` section 10.
- `S-502.AC1`: Header search box and `/search?q=`; 300 ms debounce; loading indicator within 100 ms; stale results discarded via AbortController and request counter (EC-13).
- `S-502.AC2`: States: too short (no request), loading, results by group, empty with the query shown, error with Retry.
- `S-502.AC3`: Result items link to `/movies/[id]` and `/people/[id]`; the status text is in an `aria-live` region; typing in the header box updates the URL with `replaceState` so history is not flooded.

## Business rules and edge cases

- See the BRD rules and edge cases referenced by the acceptance criteria.

## Test expectations

- Component with fake timers: one request after rapid typing; overlapping responses out of order.
- Component: every state; keyboard access.

## Definition of done

Apply `docs/backlog/definition-of-done.md` in full, plus the criteria above. No criterion is complete without command output as evidence.

Search feedback is an explicit assessment criterion (A-N5).
