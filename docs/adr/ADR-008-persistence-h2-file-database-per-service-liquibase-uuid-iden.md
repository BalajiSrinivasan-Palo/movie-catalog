# ADR-008: Persistence: H2 file database per service, Liquibase, UUID identifiers

**Status:** Accepted (D5)

## Context

Persistence is unspecified. The owner chose H2 file databases, Liquibase, and posters as files on disk.

## Decision

Each service has its own H2 database file and Liquibase changelogs. Public identifiers are UUIDs generated by the owning service. Artwork files live under `ARTWORK_DIR`, with metadata in `artwork` rows.

## Why

No external database or Docker is needed to run (NFR-OPS-01). Per-service databases preserve data ownership. UUIDs avoid enumerable ids and cross-service id collisions.

## Consequences and trade-offs

H2 file mode supports one application process per database file, so each service is single-instance, and it is not a production-grade choice. Search uses `LIKE`, not full-text indexes (ADR-009).
