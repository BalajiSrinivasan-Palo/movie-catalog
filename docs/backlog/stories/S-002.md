# S-002: Quality gates, hooks and CI

**Epic:** E00 Foundation and platform skeleton  
**Priority:** Must · **Size:** M · **Order:** 2 · **Wave:** 2  
**Status:** Draft (Phase 4)  
**Depends on:** S-001

**BRD acceptance criteria owned:** none

## Objective

Quality gates, hooks and CI.

## Acceptance criteria

- `S-002.AC1`: `./scripts/verify.sh` runs ktlint, detekt, backend tests with Kover threshold, and prints each command's real exit status.
- `S-002.AC2`: A Claude Code pre-commit hook and a CI workflow call the same script.
- `S-002.AC3`: A secret scan fails on a planted fake key (negative test of the gate).
- `S-002.AC4`: `scripts/check_traceability.py` fails if any requirement or BRD acceptance criterion has no owning story.
- `S-002.AC5`: A dependency audit step exists for backend and frontend and its output is saved to `reports/`.
- `S-002.AC6`: Two layers are delivered: a git pre-commit hook (`scripts/hooks/pre-commit`, installed by `scripts/install-hooks.sh`) that runs `verify.sh`, and the Claude Code hook in `.claude/settings.json` (already present) that blocks destructive commands; CI is a GitHub Actions workflow calling `verify.sh` (used once the repo is on GitHub).
- `S-002.AC7`: Secret scan is `scripts/secret_scan.py` (regex for keys/tokens/private keys, no external tool); `check_traceability.py` is a development-time gate only and is not required to run the app (NFR-OPS-01).

## Business rules and edge cases

- Gates must fail loudly; no `|| true` masking.

## Test expectations

- Gate negative tests: lint violation, failing test, planted secret each make the script exit non-zero.

## Definition of done

Apply `docs/backlog/definition-of-done.md` in full, plus the criteria above. No criterion is complete without command output as evidence.

## Notes

Frontend gates are added when S-003 lands (the script already has a placeholder that fails if the frontend exists but is not wired).

## Why this design (for the walkthrough)

Mandatory gates must be deterministic, not agent promises.
