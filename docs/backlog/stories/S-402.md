# S-402: Movie page credits with batched name resolution

**Epic:** E04 Credits and filmography  
**Priority:** Must · **Size:** M · **Order:** 21 · **Wave:** 8  
**Status:** Draft (Phase 4)  
**Depends on:** S-401, S-305  
**Requirements:** FR-CRD-04, FR-MOV-02, FR-PPL-03, NFR-PERF-04  
**BRD acceptance criteria owned:** AC-FR-CRD-04-1, AC-FR-MOV-02-1, AC-FR-PPL-03-1

## Objective

Movie page credits with batched name resolution.

## Acceptance criteria

- `AC-FR-CRD-04-1`: as defined in `docs/requirements/BRD.md` section 10.
- `AC-FR-MOV-02-1`: as defined in `docs/requirements/BRD.md` section 10.
- `AC-FR-PPL-03-1`: as defined in `docs/requirements/BRD.md` section 10.
- `S-402.AC1`: `ListCreditsByMovie` (limit 200, truncated flag) and one `BatchGetPeople` call for distinct person ids (call-count test).
- `S-402.AC2`: Credits grouped by role; unresolved person shows 'Unknown person' (BR-07); people-service down shows degraded names with Retry while movie data renders (EC-15).
- `S-402.AC3`: Editing a person's name is visible in the movie credits (AC-FR-PPL-03-1).
- `S-402.AC4`: Contract change: `Credit.personStatus: RESOLVED | NOT_FOUND | UNAVAILABLE` distinguishes 'Unknown person' (BR-07) from a degraded lookup (EC-15); `person` is null unless RESOLVED.
- `S-402.AC5`: Credits are ordered by role (ACTOR, DIRECTOR, WRITER, PRODUCER) then creation time, `total` is returned, and a truncated list shows 'N more not shown'.
- `S-402.AC6`: The gateway batches person lookups with a DataLoader so a movie list requesting `credits` issues one `BatchGetPeople` per request (NFR-PERF-04).

## Business rules and edge cases

- EC-14: more than 200 credits shows an explicit truncated indicator.

## Test expectations

- Unit: grouping, truncation.
- Integration: gateway resolver with fakes counts `BatchGetPeople` calls = 1.
- Fault injection: people-service stopped.
- Component: degraded state.

Apply `docs/backlog/definition-of-done.md` in full, plus the criteria above. No criterion is complete without command output as evidence.
