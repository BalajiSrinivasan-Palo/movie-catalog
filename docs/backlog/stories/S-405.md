# S-405: Block deleting a person who has credits

**Epic:** E04 Credits and filmography  
**Priority:** Must · **Size:** M · **Order:** 23 · **Wave:** 7  
**Status:** Draft (Phase 4)  
**Depends on:** S-104, S-401  
**Requirements:** FR-PPL-04, NFR-ARCH-02, NFR-REL-02  
**BRD acceptance criteria owned:** AC-FR-PPL-04-2, AC-FR-PPL-04-3

## Objective

Block deleting a person who has credits.

## Acceptance criteria

- `AC-FR-PPL-04-2`: as defined in `docs/requirements/BRD.md` section 10.
- `AC-FR-PPL-04-3`: as defined in `docs/requirements/BRD.md` section 10.
- `S-405.AC1`: `MovieService.CheckPersonCredits` and people-service call it before deleting; blocked delete returns `FAILED_PRECONDITION` with up to 10 blocking movies, mapped to GraphQL `CONFLICT` with `blockingMovies`.
- `S-405.AC2`: Movie-service unavailable or timeout → `UNAVAILABLE`, nothing deleted (fail closed, EC-16).
- `S-405.AC3`: UI explains the block and links to the movies; this story removes the interim limitation of S-104.
- `S-405.AC4`: S-405 sets `catalog.people.delete-enabled=true`; people-service has a configured gRPC client to movie-service with a 2 s deadline; `ErrorDetail.metadata["creditCount"]` carries the total and is exposed as `extensions.creditCount` so the UI can show 'and N more'.
