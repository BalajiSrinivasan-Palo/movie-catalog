# Plan S-702: Search scope menu, year picker and multi-select genres

**Story:** `docs/backlog/stories/S-702.md` · **Objective:** add the three controls from the owner's reference images. The search scope and year picker are frontend only. Multi-select genres is an additive contract change through every layer. **Three parts, each its own commit and review:** 8a, 8b (Claude verifies directly) and 8c (backend built and tested by the owner, D15).

## Preconditions
- D22 and ADR-015 approved by the owner.
- S-701 unit tests have been run green once the lockfile installs (so a later failure belongs to this story).
- 8c backend: the owner can run `./gradlew build` in their own terminal.

## Part 8a: search scope (AC1 to AC3)
Files: `frontend/src/lib/components/SearchBox.svelte`, new `frontend/src/lib/components/ScopeMenu.svelte`, `frontend/src/lib/views/SearchView.svelte`, new `frontend/src/lib/search-scope.ts`.
- `search-scope.ts`: `type Scope = 'all' | 'titles' | 'people'`, `scopeFromUrl(params)`, `searchHref(query, scope)` (omits `scope` for All), placeholder text per scope.
- `ScopeMenu`: menu-button pattern (`button` with `aria-haspopup="menu"` and `aria-expanded`; `ul role="menu"` with `role="menuitemradio"` and `aria-checked`). Keyboard as in AC1. Closes on outside click and Esc; focus returns to the button.
- `SearchBox`: scope button on the left inside the same bordered box; changing scope re-runs the search at once if there is a query; `go()` builds the URL with `searchHref`.
- `SearchView`: read `scope`; All keeps `searchAll`; Titles calls `searchMovies(q, 0)` and renders only the movie `SearchGroup`; People the same with `searchPeople`. The stale-response guard and states are reused unchanged.

## Part 8b: year picker (AC4 to AC6)
Files: new `frontend/src/lib/components/YearPicker.svelte`, new `frontend/src/lib/years.ts`, `frontend/src/lib/views/MovieListView.svelte`.
- `years.ts`: `pageOf(year)`, `yearsOnPage(start)` (20 years), bounds from `EARLIEST_YEAR` and `maxYear()` in `forms/validate.ts`.
- `YearPicker`: wraps the existing `TextField` (label, error, `inputmode="numeric"`) plus a calendar button (`aria-label="Choose from year"`, `aria-expanded`). The popover is a non-modal dialog (`role="dialog"`, `aria-label`) holding a 5×4 grid of year buttons using roving `tabindex`; previous and next page buttons; Clear and This year. Keyboard per AC5; Esc and outside click close and return focus.
- `MovieListView`: replace the two year `TextField`s with two `YearPicker`s bound to the same `yearFrom` and `yearTo` state; validation and Apply unchanged.

## Part 8c: multi-select genres (AC7 to AC9)
Contracts and backend (owner builds and tests, D15):
- `contracts/src/main/proto/moviecatalog/movie/v1/movie_service.proto`: `repeated Genre genres = 7;` in `ListMoviesRequest`, with a comment that a movie matches any listed genre and that `genre = 4` is kept for compatibility.
- `api-gateway/src/main/resources/graphql/schema.graphqls`: `MovieFilter.genres: [Genre!]`; `genre: Genre @deprecated(reason: "Use genres")`.
- `api-gateway/.../CatalogControllers.kt` (and `Views.kt` if the filter is mapped there): map `genres` to `addAllGenres`; keep mapping `genre`.
- `movie-service/.../MovieGrpcService.kt`: read `genre` and `genres`, combine into a set; reject more than 15, duplicates within `genres` or unknown values with `INVALID_ARGUMENT` field `genres` / key `movie.genres.invalid`.
- `MovieService.kt` and `Repositories.kt`: `list(genres: Set<Genre>, …)`; the predicate becomes `cb.or(*genres.map { cb.isMember(it, root.get("genres")) })` when not empty. `isMember` is a subquery, so there is no join and no duplicate rows; the count query uses the same predicates.
Frontend:
- `frontend/src/lib/api/catalog.ts`: `MovieListParams.genres: Genre[]`; send `filter.genres`.
- `GenreChips.svelte`: checkboxes instead of radios; `value: string[]`; selected chip filled with a ✕ (`aria-hidden`; the checkbox state is what is announced); summary line with Clear.
- `MovieListView.svelte`: `applied.genres: string[]`; chips apply at once and reset to page 1; Clear filters empties them.
- `frontend/e2e/support/mock-api.ts`: support `filter.genres` (any match).

## Contract changes
Additive only: one protobuf field (number 7) and one GraphQL input field; `genre` deprecated, not removed. No database change.

## Tests
- Frontend unit and component tests as listed in the story; `design-rules.test.ts` touch targets for `ScopeMenu`, `YearPicker`, `GenreChips`.
- movie-service: `MovieServiceTest` list by `{COMEDY, CRIME}` returns movies with either, once each, with the correct total; empty set returns all; `MovieGrpcTest` for `genres`, too many, duplicate, unknown, and `genre` and `genres` combined.
- Gateway: `CatalogGraphQlTest` maps `genres` to the gRPC request and still maps the deprecated `genre`.
- E2E mocked: a11y and responsive specs cover the scope menu open, the year grid open and several genres selected; screenshots.

## Security and regression
- Genres are an enum list with a size cap, validated in movie-service (business validation stays in the owning service); the frontend mirrors it only for UX.
- No new dependency. The scope is a fixed set read from the URL; unknown values fall back to All.
- Regression risk: the S-701 genre-chip tests change from radio to checkbox; assertions are updated to the new behaviour, not removed.
