# Plan S-701: Visual refresh (poster grid, cinematic detail, drag-and-drop upload)

**Story:** `docs/backlog/stories/S-701.md` · **Objective:** restyle the lists, detail pages and artwork uploader to the approved mockups (Options A and C plus drag and drop) without changing any contract, validation or behaviour. **Implement and review in three parts:** 7a (tokens, header, lists), 7b (detail pages), 7c (drop zone). Each part is a separate change the reviewer can check on its own.

## Preconditions
- D21 and ADR-014 approved by the owner. Until then nothing in `frontend/src` changes.
- The current frontend gates are green (`pnpm check && pnpm lint && pnpm test && pnpm build`), so any later failure is caused by this story.
- Frontend only: Claude runs and verifies every command here directly (npm is reachable; D15 does not apply).

## Part 7a: tokens, header and list pages (AC1 to AC5)
Files: `src/lib/styles/global.css`, `src/lib/components/AppHeader.svelte`, `src/lib/views/MovieListView.svelte`, `src/lib/views/PeopleListView.svelte`, `src/lib/components/Skeleton.svelte`, new `src/lib/components/PosterCard.svelte`, new `src/lib/components/GenreChips.svelte`, new `src/lib/initials.ts`.
- Tokens: add `--color-accent-tint` (pill and chip background), `--color-hero-bg`, `--color-hero-text`, `--color-hero-muted`, `--radius-card: 0.75rem`; keep every existing token and its contrast note. No hex colour is written outside `global.css`.
- Header: white bar with a bottom hairline; active nav link becomes a tinted pill (`--color-accent-tint` background, `--color-primary` text). Touch targets stay `var(--touch-target)`.
- `PosterCard`: one `<a>` wrapping `ArtworkImage` (2:3 box, `object-fit: cover`), title and a meta line. Props: `href`, `title`, `imageSrc`, `meta`. Used by the movie list (7a) and the filmography (7b).
- Movie grid: CSS grid, 2 / 3 / 5 columns at the existing 600 and 960 px breakpoints; `minmax(0, 1fr)` so long titles wrap instead of widening the page.
- `GenreChips`: a `fieldset` with a `legend`, an "All" radio plus one radio per entry in `GENRES`; the radios are visually styled as chips with the input kept in the accessibility tree (not `display: none`). On change it calls the same `apply` path the current genre `Select` uses, so URL state and paging reset behave as today. Sort `Select` and the year inputs stay in the form beside it.
- People grid: same grid, with an initials circle from `initials(name)` (first letter of the first and last words, uppercased, using `Array.from` so non-Latin and surrogate-pair letters are not split).
- Skeleton: a poster-shaped variant for the grid.

## Part 7b: detail pages (AC6 to AC9)
Files: `src/lib/views/MovieDetailView.svelte`, `src/lib/views/PersonDetailView.svelte`, `src/lib/views/CreditsSection.svelte`, new `src/lib/components/HeroBand.svelte`, `src/lib/components/design-rules.test.ts`.
- `HeroBand`: a full-width section with `--color-hero-bg`; slots (snippets) for poster, heading block and actions. Buttons and links inside it get a hero variant (light outline on dark) via a class, still 44 px.
- Movie detail: back link, poster, `h1` title, meta line, genre pills, synopsis, Edit and artwork actions inside the hero; Delete stays where it is in the current page so the confirm dialog flow is untouched.
- `CreditsSection`: render credits as a card grid; keep the existing add, edit and remove controls and their dialogs exactly as they are, only the list markup and CSS change. `personStatus !== 'RESOLVED'` renders the dashed "Person unavailable" card.
- Person detail: hero with name, born date, bio, Edit and Delete; filmography uses `PosterCard` with `movie.thumbnailUrl` and meta "year · role"; pagination unchanged; the blocked-delete alert unchanged.
- Contrast: add the hero tokens to `design-rules.test.ts` (`--color-hero-text` and `--color-hero-muted` on `--color-hero-bg` at least 4.5:1; accent text on `--color-accent-tint` at least 4.5:1). Add `HeroBand.svelte` to the touch-target list if it styles controls.

## Part 7c: drag-and-drop uploader (AC10 to AC13)
Files: `src/lib/components/ArtworkUploader.svelte`, `src/lib/components/ArtworkUploader.test.ts`, `src/routes/+layout.svelte`.
- Refactor `choose(event)` into `accept(file: File)`, which holds today's logic (store the file, run `validateArtworkFile`, start). The file input's `onchange` and the new `ondrop` both call `accept`, so there is one code path (AC12).
- The drop zone is the existing `<label>` around the file input, restyled as a dashed box. The input stays focusable and labelled; it is visually covered by the zone text but not hidden from assistive technology.
- `dragenter` / `dragover`: only when `event.dataTransfer?.types` includes `"Files"` and the uploader is not busy, call `preventDefault()` and set `dragging = true`. `dragleave` (when leaving the zone itself, not a child) and `drop` reset it. `drop`: take `files[0]`; if `files.length > 1`, set a status message "Only the first file was used."; ignore when busy or when there is no file.
- AC13: in `+layout.svelte`, a `window` `dragover`/`drop` handler that calls `preventDefault()` only for file drags, so a missed drop does not open the image in the tab. It does nothing else.
- Copy: "Drag an image here or choose a file", hint "JPEG, PNG or WebP · up to 5 MB", drag state "Drop to upload" plus "Replaces the current artwork" when `hasArtwork`.

## Security and regression
- No `{@html}` (the existing static test keeps guarding this); initials and all names are text nodes.
- No new dependencies of any kind.
- Dropped files take the same client checks as chosen ones; the server stays the authority (S-304 AC3, S-301).
- The window drop handler only prevents the default navigation; it never reads the file.
- Regression risk is in selectors used by existing tests and E2E. Any test edited is listed in the report with the reason; assertions are not weakened.
